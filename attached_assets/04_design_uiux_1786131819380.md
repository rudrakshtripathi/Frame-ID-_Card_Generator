# Design / UI-UX — HH Goa 2026 Frame Generator

## 1. Design principles
- **Mobile-first, single-thumb operable.** Every primary action reachable in the bottom two-thirds of a phone screen.
- **On-brand from the first pixel.** The upload screen itself must look like HH Goa 2026 — event colors, wordmark/logo, and a real preview of the frame style — not a generic file-upload utility with a logo bolted on.
- **No dead states.** Every screen has a visible next action; no bare spinners with no context.
- **Minimize taps.** Upload → Result should be reachable in 2 taps (open picker, select photo). No intermediate confirmation screens.

## 2. Screen-by-screen

### 2.1 Landing / Upload
- Top: HH Goa 2026 wordmark/logo, small tagline ("Get your builder frame").
- Center: large preview of an example frame (a sample avatar already inside the frame) so users know exactly what they'll get before uploading — this also does double duty as branding proof.
- Primary CTA: full-width button, high-contrast, "Upload your photo" — opens file/camera picker.
- Secondary microcopy under CTA: "JPG, PNG, or iPhone photos — takes a few seconds."
- No navigation clutter, no login/signup link anywhere on this screen (reinforces "no gate").

### 2.2 Processing (in-place, not a new screen)
- The example/preview frame from landing morphs into a blurred/skeleton version of the user's actual photo inside the frame (if feasible — read the pixels immediately and show a low-res pass while final compositing finishes) so it feels like *their* result is materializing, not a generic loader.
- If a full skeleton isn't feasible in time, a simple progress affordance inside the frame slot (not a full-screen spinner) is the fallback.

### 2.3 Result
- Full-width final graphic, centered, generous padding — this is the hero of the screen.
- Two stacked buttons directly below the image (mobile): 
  1. Primary: "Download" (filled button, brand color)
  2. Secondary: "Share to X" (outline button, X logo)
- Small tertiary link below: "Try another photo."
- Result image itself should have a subtle drop shadow / card treatment so it reads as "the deliverable," distinct from UI chrome.

### 2.4 Share page (`/s/[id]`)
- Same visual language as Result screen: image centered, brand header.
- CTA: "Make your own frame →" back to landing (viral loop).
- This page is intentionally simple since most traffic to it is the X crawler, not humans — but it must not look broken to the humans who do click through.

## 3. Visual system
- **Color:** derive 1 primary + 1 accent color from HH Goa event branding (flag/logo colors if available — placeholder: deep teal/ocean blue as primary nodding to "Goa," warm accent for CTAs). Confirm against actual HH Goa brand guidelines/logo before final build — don't invent brand colors in a vacuum.
- **Typography:** one bold display face for headlines (event name, "Download"/"Share" buttons), one clean sans for body/microcopy. Avoid more than 2 typefaces.
- **Frame design itself:** must include event name/year and a recognizable motif (not just a thin colored ring) — a thin border alone reads as "generic badge," which the brief explicitly warns against. Aim for a design element (wave motif for Goa, palm silhouette, or event logo lockup) integrated into the frame border/corners.
- **Iconography:** minimal — X share icon, download icon, upload icon. Use recognizable standard icons (Lucide or Heroicons), don't invent custom icon language for a shortlisting task.

## 4. Accessibility
- Contrast ratio ≥4.5:1 for all text on buttons/backgrounds.
- Upload button reachable via keyboard (native `<input type=file>` + `<label>` pattern, not a div with onClick only).
- `alt` text on the generated result image ("Your HH Goa 2026 builder frame").
- Error messages announced via `aria-live="polite"` region so screen readers catch validation failures.

## 5. What NOT to do (explicitly, given the brief's warnings)
- Don't ship a plain circle border + logo watermark and call it "on-brand" — the brief calls this out directly ("not a generic badge with a logo pasted on").
- Don't add a signup/email-capture step before showing the result, even a "soft" one — brief is explicit: no gate before the result.
- Don't rely on a manual crop step as the only path to a good result — most users on a shortlisting-task deadline won't crop; auto-fit must carry the default case.
